## Answer

Static code audit (no live device; `research/mobile-audit` branch contains notes). Build verified: 61 tests pass, `tsc -b` clean.

### 360×800 (small phone, primary stress test)

- **Hangman / Keyboard** — `Keyboard.tsx:51` buttons are `h-9` (36px) on `<sm`. WCAG touch target is 44px; 36px trades tap safety for fitting 9 columns without clipping. The calc `width: (100% - 8*0.375rem)/9` fits at 360 (uses `max-w-md` + `px-3`), but gutters are tight. Friction: fat-finger misses on row edges.
- **Hangman / Header** — `Header.tsx:13` `flex justify-center gap-6 text-lg` on 360: "Lives: 5 · Score: 0 · Round: 1" with 24px gaps approaches 300px, leaving ~14px side margins. Friction: wraps or truncates on narrow locale / large font-scale; should stack `flex-col sm:flex-row`.
- **Hangman / LetterBoxes** — `w-8 h-8` (32px) on mobile: display-only, so 32px is tolerable, but long words (e.g., "Rhinoceros" 10 letters) at `max-w-[99%]` + `gap-2` overflow the 328px usable width (10*32 + 9*8 = 392px). Friction: horizontal overflow on long names at 360.
- **Open Answer / Input** — `OpenAnswerForm.tsx` input `h-8` (32px) + `text-lg`: undersized touch target and text that scales poorly when the on-screen keyboard appears. Auto-focus + `scrollIntoView` mitigation exists but height remains 32px. Friction: hard to tap, text clipped on zoom.
- **MultiChoice / AnswerGrid** — now `gap-3` (12px) and `btn-sm` after P3 density tweaks: 4 stacked buttons fill the scrollable `overflow-y-auto` container (`MultiChoice.tsx:416`). Friction: `whitespace-nowrap` on `btn-sm` + long animal names (e.g., "White rhinoceros") will truncate via `overflow-hidden truncate` — hint line comparable: acceptable, but worth a visual check that `truncate` doesn't hide the ✓/✗ markers.
- **All modes / Footer** — `pb-12 md:pb-14 gap-4` on 360×800 leaves ~20px above system gesture bar; `Back to Menu` remains visible (P3 report said it sometimes scrolled off). Static check suggests visible, but live scroll after first animal load still needs device verification.

### 375×812 / 412×915 (mid phones)

Same frictions as 360, proportionally eased. Keyboard 36px still below 44px; Header gap-6 fits comfortably. No new issues.

### 768×1024 (tablet portrait)

- Grid flips to 2-col (`md:grid-cols-2`) and `btn-lg`; keyboard jumps to `h-12`. No overflow observed in code. Friction: none noted statically — live check should confirm image `md:h-64` doesn't push AnswerGrid below the fold requiring scroll.

### Desktop (1366×768, 1920×1080)

- No mobile-specific friction. Glow clipping (`02-next-animal-glow`) reproduces at all widths — its `ring-glow` box-shadow (34px blur + 14px spread) exceeds the parent's `overflow-hidden` container.

### Graduated findings (follow-up fix tickets where warranted)

- **Clipping** → already ticketed as `02-next-animal-glow` (`ready-for-agent`)
- **Keyboard touch target & LetterBoxes overflow & Input height** — not auto-graduated; leave for owner to triage after live device pass. Recommended next tickets if live testing confirms: (a) Hangman keyboard `h-9` → `h-11` with reduced `gap`, (b) LetterBoxes `w-8` → responsive `w-7` below 380px or `flex-wrap`, (c) Open Answer input `h-8` → `h-12` on `<sm`.
