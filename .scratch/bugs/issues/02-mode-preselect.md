# Game Options mode preselect ignores home card

Status: resolved
Type: bug
Category: bug

> *This was generated by AI during triage.*

## Answer

**Root cause verified:** `src/components/home/ModeTiles.tsx:33` called `onStart?.()` with no mode intent — the handler was `() => void`. `src/components/GameOptions/GameOptions.tsx:29` initialized `selected` from `persistence.progress.load("mode")`, so the last saved mode always won regardless of which card was tapped.

**Fix applied on `fix/mode-preselect`:**
1. `ModeTiles` tap now emits the card's `mode.id` — `onStart?: (modeId: string) => void`
2. `src/components/Main/Main.tsx` forwards it; `src/App.tsx` calls `setMode(modeId)` before `setRoute("options")` — so the existing `NavigationState.mode` (already persisted in the `navigation` envelope) carries intent forward
3. `GameOptions` accepts a new `initialMode?: string` prop (added to `GameOptionsProps` in `src/types/GameOptions.ts`) and its `useState` initializer uses **preselect precedence**: `initialMode ?? persisted ?? OPTIONS[0].id`

**Verification:**
- New regression suite `src/test/modePreselect.test.tsx` (3 tests): tapping each of the three cards preselects that tile (`aria-pressed` true) AND persists `mode`; direct navigation without card context falls back to saved mode; no context + no saved mode falls back to Multiple Choice

**Summary:** Tapping a Mode Card on the home page always lands on the *previously toggled* mode in Game Options, not the tapped one

`src/components/home/ModeTiles.tsx: onClick={() => onStart?.()}` just does `setRoute("options")` via `App.tsx` — it carries no mode intent. `src/components/GameOptions/GameOptions.tsx` initializes `selected` from `persistence.progress.load("mode")`, so it shows whatever `mode` was last saved, regardless of which of the three home tiles ("Multiple Choice", "Open Answer", "Hangman") was tapped. `App.tsx` navigation (`route`/`mode` + `NavigationState`) and the duplicated `ModeTiles` on the home page vs in Game Options are the two surfaces.

**Verification performed during triage:**
- **Redundancy check:** searched `src/components/home/ModeTiles.tsx` and `src/components/GameOptions/ModeTabs.tsx` — no existing prop carries `mode.id` forward; `onStart` is `() => void` in both places. No prior fix.
- **Prior rejection:** checked `.out-of-scope/` — no prior `wontfix`.
- **Repro:** tap each home Mode Card → `ModeTabs` `aria-pressed` should match the tapped card's id, but currently matches the last persisted value.

**Desired behavior:**
Tapping a specific Mode Card preselects *that* mode on the next screen, while preserving the existing "survives refresh" persistence: a direct navigation to `/options` (no card context) still shows the last saved mode, and a refresh on the options screen keeps the preselected value. The home `ModeTiles` ids and the `GameOptions` `OPTIONS` ids already align by `mode.id` (`multiple-choice`, `open-answer`, `hangman`).
