## Answer

**Root cause verified:** `src/data/animals*.json` still contains 20 `plus.unsplash.com/premium_photo` entries (e.g., `b-1 American Bison`, `b-4 Barracuda`). Homepage was decoupled to `src/data/homePhotos.ts` in #40, but `src/components/MultiChoice/MultiChoice.tsx: loadNewAnimal` still draws from the full dataset via `useAnimals` + `animalQueueRef`. Its `new Image()` preload had `onload`/`onerror` handlers but no timeout — if the browser never fires either event (hanging premium preview), `isImageLoading` stays `true` forever and the `DisplayCard` spinner never resolves. Repro: start MC repeatedly until a premium animal is picked; observe `isImageLoading` stuck.

**Fix applied on `fix/mc-images` (this branch):** wrapped the `new Image()` preload in `MultiChoice.tsx:163` with a 5s `setTimeout` guard and a `settled` flag. `onload`/`onerror` now clear the timeout and check `settled`; the timeout path logs "Image load timed out, picking another.", clears `isImageLoading`, saves progress, filters the animal from `animalQueueRef` (anti-infinite-loop, same as `onerror`), and calls `loadNewAnimal()` for the next candidate. Every branch now guarantees termination to either the image or the next animal's fallback within ≤5s, preserving the existing `isImageLoading` → image / "No image available" contract.

**Verification:**
- `pnpm exec tsc --noEmit` — clean
- `pnpm test` — 11 files, 61 tests passed (including `src/test/restoreFlow.test.tsx` MultiChoice restore)
- Manual: premium animal picked → timeout path fires after 5s → spinner clears, next animal loads; non-premium → onload path unchanged

**Out of scope respected:** no dataset replacement, no homepage coupling.
